博客整体审查 · 2026-10-02

本次审查基于当前工作区源码、本地正式构建站点 http://127.0.0.1:8080，以及少量私有预览页检查。公开内容的判断以 8080 与 draft/hidden 规则为准。没有改动博客实现、文章或发布状态。

结论：极简排版、三栏阅读、目录和相册已经形成了风格。下一轮最值得投入的是内容完整性、入口可发现性、移动端一致性，以及字体与过渡动画的成本。保留现有视觉方向，先修复下列实际缺陷。

**检查范围与证据**

- 扫描 56 篇 Markdown/MDX：50 篇公开、6 篇草稿。公开文章全部为中文；Golang 34 篇、Algorithm 10 篇、LLM 4 篇、Tool 1 篇、博客 1 篇。
- 读取 55 个页面，并检查其中提取到的 102 个不同站内链接或资源地址，发现 7 个 404 地址。此数字不包含另行抽查的历史链接，也不代表全部外链已检查。
- 浏览器检查桌面 1920×878、移动视口 390×844；实际操作移动目录、明暗切换、相册堆叠/网格切换。移动视口模拟不等于真机兼容性测试。
- `pnpm exec astro check`：104 个文件，0 errors、0 warnings、1 hint；内容同步期间出现了数学解析提示。类型检查通过不能证明文章渲染正确。
- 以下性能数字来自本地构建与浏览器资源记录；未进行公网弱网测试或真实用户 Core Web Vitals 统计，不据此声称线上 LCP/INP/CLS 达标或不达标。

**P1：先修复影响阅读与导航的问题**

1. 移动端首页没有有效留白。

   390px 视口下，首页 `.layout-shell` 的 computed padding 为 `0px`，站名、导航和列表贴着屏幕边缘。文章页则是 `24px 22px 40px`。源码在 `src/layouts/Layout.astro:51` 使用 `p="x-[min(7.25vw,3.731rem)] y-10"`，已部署样式中没有找到对应的 padding 规则。建议优先检查构建后的属性样式生成，或直接使用可靠的 CSS/class 设置统一页面边距。验收应覆盖首页、标签、关于页在 320/390/768px 下的首屏，不能只检查开发预览。

2. 文章侧栏的子标签链接进入 404。

   `src/components/PostSeries.astro:15` 使用 `/tags/${tag}/`，而标签页使用完整层级。比如 `/tags/Go数据结构/` 为 404，`/tags/Golang/Go数据结构/` 为 200。还发现 Go内存管理、Go并发编程、Go语言基础、Go其他、GoPackages、Go关键字的同类问题。建议让系列工具返回完整标签路径，复用 `getTagPath()`；不要只修改某一条链接。验收：公开文章中所有侧栏标签标题和正文标签均可访问。

3. 发布内容中仍有迁移和编辑残留。

   - `src/content/posts/Golang/包/pprof.md:13` 起整篇带 `1|`、`2|` 等行号前缀。实际页面中标题和代码未正常解析，目录缺失，并出现红色 KaTeX 错误区域。需要恢复正常 Markdown，而不只是隐藏报错颜色。
   - `src/content/posts/Golang/1 并发编程/sync.Pool.md:300` 的 `![[pool-structure.png]]` 没有转换为网页图片。
   - `src/content/posts/Algorithm/Tree.md:43` 的 `[toc]` 直接残留在正文。
   - `src/content/posts/Golang/1 并发编程/sync.WaitGroup.md:118` 保留“以下是针对 [[sync.WaitGroup]] 文章的完善建议……”等编辑建议文字，应整合为正式正文并消除重复结构。

   建议加入发布前内容检查：识别非代码区的 Obsidian 嵌入、编辑提示语、行号前缀、缺失图片与公式错误；不要把代码中的二维数组 `[[...]]` 误报为双链。

4. 至少存在一处可复现的技术表述错误。

   `src/content/posts/Golang/0 基础/数据结构/Map.md:37` 写“chan、map、func 不可比较”。本地 `go run` 已验证 `map[chan int]string` 能正常创建和读取，channel 可以作为键。建议修正该句，并对 Go 基础文章进行事实复核。源码分析类文章增加适用 Go 版本、源码依据和复核日期；本轮没有逐篇核验所有算法与运行时实现细节。

5. 历史文章链接没有迁移兜底，404 页面也未接入本地 nginx。

   旧站保留的 `/2025/07/28/Golang/包/Quic/` 和 `/2025/07/28/Golang/包/Golang Test 工具指令/` 对应内容在新站存在，但旧地址均返回 404。另抽查 `/2025/12/04/CLAUDE/` 也为 404，是否保留该文章需要单独决定。建议为仍公开的同一内容建立旧地址到新 slug 的映射，不把已移除或私有内容重新公开。

   当前 `/404.html` 存在，但未知路径返回 nginx 默认错误页。`docker/nginx.conf` 应接入自定义 404，提供首页、专题和搜索入口，同时保留 404 状态。历史重定向的实现应按实际部署环境选择；本地 nginx 检查不代表 GitHub Pages 的线上行为。

**P2：内容组织和站点定位**

6. 首页需要帮助读者选择阅读路径。

   当前首页一次展示 50 篇公开文章，桌面页面高度约 7882px；已有按年份分组，但 `src/pages/[...lang]/index.astro:32` 丢弃了年份，只显示分隔线。没有搜索入口。建议首页展示“精选 3 篇 + 最近 8–12 篇 + Go / 算法 / LLM 专题入口”，其余放入明确的归档页；也可以保留时间流，但补年份标题、主题筛选及搜索。先采用静态搜索和简单筛选即可，是否引入具体搜索依赖另行评估。

7. 为文章补充摘要和阅读预期。

   50 篇公开文章中，45 篇没有独立 description，46 篇没有 updated 字段。现有程序会自动生成摘要，因此不是 SEO description 全部为空；问题是自动截取通常缺少明确的读者收益。建议优先整理高价值文章：一句话讲清“解决什么问题、适合谁、读完得到什么”。例如将 `[Go] Map` 展示为“Go Map：从使用方式到扩容原理”，分类放到轻量标签中。移动列表目前完全隐藏摘要，建议至少保留一行可辨识的简介。

8. 专题目录与标签需要统一语义。

   当前 tags 同时承担“层级分类”和“标签”两种角色，PostSeries 又用末级标签相等匹配，容易产生路径和分组不一致。还有 `GoPackges` / `GoPackages` 拼写分裂。建议明确 category、tags、series 的职责；学习系列增加显式顺序及前后篇，而不是仅按发表日期倒序。可以先规范现有 front matter，再决定是否调整 schema。

9. 关于页与语言入口应与实际内容匹配。

   中文关于页只有“主题更换 迁移中”，英文为“building”；公开文章全部为中文，但首页仍显示语言切换，进入英文首页后没有文章。建议先完成中文关于页：作者身份、关注方向、推荐阅读、联系/反馈入口、更新方式。英文内容准备好前可以收起全局语言入口，或让英文页明确说明可阅读的中文内容。关闭全局英文入口时需保留已有有效外部链接的合理去向。

10. 增加轻量反馈和持续阅读入口。

    目前已有 RSS、GitHub、相关文章，不需要重复建设。可以在文章末尾补充明确的“报告错误/联系作者”，并让 RSS 的作用更易理解。是否开启评论取决于维护意愿；不必为了功能完整而直接接入第三方评论。对转载、摘录和学习整理内容，统一标注来源与个人补充的边界。

**P2：主题、展示与交互**

11. 统一三个页面体系的视觉关系。

    首页是右侧固定站名/导航，文章页变为顶部导航与三栏，相册又是全屏绿色调界面。各自有设计意图，但切换时品牌位置、阅读重心和操作位置变化较大。建议先统一字体层级、颜色 token、间距和返回规则；相册可以保留独立展示方式。文章页三栏布局有实际价值，应保留。较浅的侧栏文字可提高对比度，日期使用更易辨认的数字字体，书写风格字体集中用于站名等品牌元素。

12. 放大触控区域，并保持正文的稳定呈现。

    移动首页的主题/语言按钮实际只有 16×16px，而文章页有更大的点击区。建议图标保持视觉尺寸，交互区域统一扩大到约 44×44px，并提供清晰的焦点反馈。目录弹层已经能打开并把焦点移入目录，主题切换也已验证正常，应围绕现有实现优化。正文有逐段淡入，前 16 个子元素不断增加延迟；可以缩短或减少长文动画，以便读者跳转后立即阅读。

13. 相册优先让照片更容易看清和找到。

    堆叠与网格切换可用，已有可视窗口渲染、资源缓存上限和减少动态效果时的网格回退。390px 下，初始堆叠照片较小且倾斜，顶部和底部留白较多；当前网格固定行距使横图之间也有明显空白。建议把“移动端默认网格”作为可试验的体验方案，增加首次操作提示，使用更紧凑的自适应行高，并记住用户选择。堆叠模式可作为保留的特色展示。此项属于体验取舍，不是功能故障。

**P2：性能与工程维护**

14. 首页过渡动画的 HTML 成本过高。

    本地首页未压缩 HTML 为 285,990 字节，其中 101 个 style 块共 222,188 字节，约占 78%。检查产物可见大量按文章标题和时间生成的 named transition 规则，对应 `src/components/PostList.astro:39`、`:57`。建议只保留必要的过渡对象、减少首页条目，或者取消列表逐项共享元素过渡。这里是解压后的体积，不等于网络传输量；gzip 会减少传输，但解析和样式处理成本仍应关注。

15. 字体与缓存优先减负。

    桌面首页本次资源记录有 14 个字体请求，共约 690 KB transferSize。`src/layouts/Head.astro:64` 起全局预载多种字体；导航/站名字体会引入额外中文分片。建议正文和普通 UI 使用系统字体，品牌字单独做小字集；仅预载首屏确定使用的字体。

    本地 `docker/nginx.conf:2` 除 `/_astro/` 外统一 `no-store`，字体请求已确认返回该响应头。若此配置用于实际读者访问，字体会反复传输。建议按资源类型区分：带内容哈希的资源长期缓存，固定文件名字体使用版本化 URL 后再长期缓存，HTML 使用适合发布机制的再验证策略。开发或本地预览有意禁用 HTML 缓存可以保留，不能直接认定公网同样配置。

16. 减少与当前页面无关的资源和请求。

    `astro.config.ts:37` 开启所有链接 viewport 预取。首页本次静置已预取 6 个文章页面；可改为明确意图触发或限制预取范围，并考虑节流和节省流量偏好。Head 还会在无公式首页加载 KaTeX CSS，可以依据页面内容决定。

    相册在 `StackGallery.astro:182` 下载 `photo.src` 后再通过 canvas 缩小；这能降低后续绘制压力，但不会减少已下载的原图。建议提供缩略图/中图/原图层级：列表使用适合屏幕的图片，打开大图再获取高分辨率版本。现有图片缓存和虚拟窗口应保留，不需要重做整套相册。

17. 为发布流程补上真正对应风险的检查。

    当前类型检查能通过，但无法发现本文中的内容残留、侧栏 404、移动 padding 丢失。建议发布时增加：构建产物站内链接检查、非代码正文残留检查、首页/长文/标签/相册的固定视口截图检查，以及关键页面资源体积记录。先把本次发现转成少量有效检查，不必为每个样式规则编写测试。

**建议实施顺序**

- 第一批：移动 padding、7 个子标签地址、Pprof/Obsidian/编辑残留、Map 表述错误；完成后验证公开文章阅读路径。
- 第二批：历史地址映射与自定义 404、关于页和英文入口、标签命名统一。
- 第三批：首页精选/专题/搜索、摘要、系列阅读顺序、字体和过渡动画减负。
- 第四批：相册移动展示、图片分辨率分级、视觉 token 与触控细节。

可以先用几个明确指标验收：站内断链归零；发布内容无已确认的迁移残留；移动页面留白一致；首屏字体请求数和字节明显下降；首页不再为全部历史文章生成大量过渡样式。线上性能提升应在最终部署环境复测后判断。
